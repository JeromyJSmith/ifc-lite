Unit normalization now rescales the length attributes of IFC4.3-only classes; `@ifc-lite/parser` gains `getAllAttributesForEntityAcrossSchemas`, the TYPED counterpart of `getAttributeNamesAcrossSchemas`.

The merged exporter's `unitReconciliation: 'normalize'` derives each entity's length/area/volume slots from the parser's IFC4-pinned registry, which answers an empty attribute list for every class outside the pin — so the plan for an IFC4.3-only class came back empty and its lengths survived normalization **unscaled**: a silently wrong number, not a missing one. `IfcAlignmentCant.RailHeadDistance`, every radius/length of `IfcAlignmentHorizontalSegment`/`IfcAlignmentVerticalSegment`/`IfcAlignmentCantSegment`, the spiral constants (`IfcClothoid`, sine/cosine/polynomial spirals), `IfcPointByDistanceExpression` offsets and `IfcOpenCrossProfileDef.Widths` all kept their old magnitude while the rest of the model changed unit. Measured on the buildingSMART `Railway_project_simple` IFC4X3 fixture: 34 entities carrying 138 length-typed slots would be left unscaled by a unit-changing merge; on `859_linear_placement_of_signal`, 60 entities / 208 slots — alignment geometry, the core of any rail/road model.

The blocker recorded against this defect — "the union has names, no types" — turned out to be false: the repo already commits a fully typed IFC4X3 registry (`packages/codegen/generated/ifc4x3/schema-registry.ts`, generated from the bundled `IFC4X3.exp`). A new generated table (`scripts/generate-union-attr-types.mjs` → `packages/parser/src/generated/attr-types-union.ts`, CI-checked for drift) carries the typed attributes of the 116 entity classes in IFC4X3 but not in the IFC4 pin, and `getAllAttributesForEntityAcrossSchemas` resolves through it — pinned result unchanged whenever the pin has one, so no IFC4/IFC2X3 plan moves. Emitting only the delta is safe because the registries' sole measure-relevant divergence on a shared class is `IfcSweptDiskSolidPolygonal.FilletRadius` narrowing to IfcNonNegativeLengthMeasure at the same slot. `IfcMapConversionScaled` stays excluded from rescaling by the existing `IFCMAPCONVERSION` prefix guard (georeferencing offsets live in the CRS unit). IFC2X3-only classes still answer empty — no IFC2X3 EXPRESS source is bundled to type them from.
